# CairnShop v0.3.0 — Operations API and Vue3 Console

The operations surface and the SPA are in place: operators can edit versioned
CairnKV configuration, roll back, manage products, inspect audits, and see
cluster status from the same app the storefront runs on.

## Highlights

- **Versioned config writes**: `PUT /api/v1/ops/config` serializes writers
  with MySQL `GET_LOCK`, appends the previous document to `history` (max 20),
  increments `version`, and records `updated_by` / `updated_at`.
- **History and rollback**: `GET /api/v1/ops/config/history` and
  `POST /api/v1/ops/config/rollback`.
- **Audit**: config writes and ops catalog writes go to `audit_logs`;
  `GET /api/v1/ops/audit` returns the latest entries.
- **Ops status**: MySQL health, CairnKV role/term/commit/WAL, config cache age
  and staleness.
- **Ops catalog**: product list including draft/archived products.
- **Vue3 SPA**: storefront (catalog, auth, cart, checkout, orders) and ops
  console (config, products, audit, status).
- **Deployment scaffolding**: Dockerfiles, Compose profiles for VPS TLS and
  Cloudflare Tunnel, and `docs/DEPLOY.md`. Not yet exercised on a public host.

## Validation

- Backend: Linux Debug build and `ctest`.
- Frontend: `npm install && npm run build` (Vite 5.4, 1633 modules; JS
  1.08 MB / CSS 365 KB; chunk-size warning noted for W9).
- Ops console: save config -> version increments -> history shows the old
  version -> rollback restores it -> audit entry appears.
- Storefront: login -> cart -> checkout with the welcome10 promo -> pay ->
  order list.
- Status page: MySQL, CairnKV and config cache fields populated.

## Known limits

- Prepared statements, rate limiting, CSRF, metrics, CI, e2e and load tests
  remain W9.
- The Nginx image still serves a placeholder; wiring `frontend/dist` into the
  production image is W9.
